# Learnings — PR #35666 pr-complete

- Interaction-on-change is not a finished-price gate. `hasScaleValidationInteraction` was reused from scale *validation* errors, where firing as soon as the user types is correct. The far-from-market warning needed the limit path's blur/commit flag. The existing test only covered the empty initial state, so a partial start with a filled end still warned. Reviewers caught the mismatch between the comment claiming "mid-keystroke" protection and the flag that actually turns on in `onStartPriceChange`.
- A single blur flag only works if change clears it. Setting `hasBlurredScalePrice` on blur without resetting on the next keystroke would reintroduce the same bug the moment the user edited a finished ladder. The limit form already does this (`setLimitPrice` clears `hasBlurredLimitPrice`; `commitLimitPrice` sets it).
- Flaky-test CI still reports J9/J10/J3 on files whose `beforeEach` already resets state and whose spies already `mockRestore()`. Historical rate 0 is not proof by itself, but reading the actual `beforeEach` was. The bot's suggested J9 diff would have replaced lets with a duplicate `beforeEach`.
- `renderHook` wrapped in a helper infers `rerender(props: Props)` as required (`unknown`), while an inline `renderHook(() => ...)` infers `void` and allows `rerender()`. That tsc error only showed up after rebase onto main; `rerender(undefined as never)` unblocked the file without changing `renderProForm`.
